# XA401のチューナー数と同時配信

XA401の取扱説明書はトリプルチューナー搭載と説明している。本体は3チューナーであり、旧Bridgeの1局上限はソフトウェアの保守的な制限だった。「単一チューナー」という旧エラー文や説明は訂正する。

ネットワーク配信数は物理チューナー数と別。J:COM公式は、DMS配信・LAN録画・ダビングを合わせて最大2動作、STBでネット動画を視聴中は最大1動作とする。変換処理にも別の制限がある。3チューナーだから3番組をネットワーク同時配信できる、とは判断しない。

## 実機確認 2026-11-15

NHK総合・テレビ朝日のoriginalリソースを同じPCから同時受信し、双方のAKE完了を確認。1本目は同じ受信セッションを維持し、受信量が770,048 Bから14,371,284 Bへ増加、途中EOFなし。2本目は54,602個すべての188 B TSパケットで同期正常、SITも3回取得した。長時間・全チャンネルの組合せを保証する検査ではない。

最初の比較は既存ブラウザーの切断と重なり、1本目の継続を証明できず成功と数えなかった。その後、両受信を自分で保持する上記の検査で確認した。

## Bridgeの2系統管理

`max_streams`を1または2に設定する。設定例と実環境は2、省略した旧環境は1を維持する。2の場合はquality: originalが必要で、2系統の変換配信へ暗黙に切り替えない。同じ局の複数視聴は1受信を共有し、別局は別枠を使う。

1局視聴中は空いた1枠で番組情報を収集できる。視聴2局なら収集は待機する。新しい視聴が収集用の枠を必要とする場合は収集だけを中断する。視聴2局が使用中の第3局要求は503。`/api/tuners`は受信スロットの表示で、物理チューナーを個別制御するAPIではない。`/health`のstreamsで各受信の視聴・背景収集数を確認できる。

2枠管理を通した実機検査でも、視聴セッション継続・途中EOFなし・受信10,265,176 Bと、その間の背景収集1局成功を確認。最初の16秒の検査は配信データが出ないBS候補が続き、収集成功0だったため、同時収集成功とは数えなかった。後の正常配信局での再検査で成功した。

ローカル35テストとWindows・Ubuntu・macOSのCIが成功（f661668 / 43677515703）。他の正規アプリ、LAN録画、STBネット動画などが枠を使っている場合は2本目を取得できないことがある。外部の動作を停止せず、3本目のDMSや同時変換は試していない。
