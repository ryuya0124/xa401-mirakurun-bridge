# KonomiTVの予約一覧とPC録画予約

XA401構成で標準画面がEDCB専用の予約APIを呼び、HTTP 422になる問題に対応した。
LAN HTTPS入口で`/api/recording/reservations`と`/api/recording/presets`を、
Bridgeの`/api/xa401/konomi/recording/...`へ中継する。
KonomiTVのバックエンド種別をEDCBと偽装せず、KonomiTV本体のソース・DBも変更しない。
直接KonomiTVの内部ポートへ接続した場合は従来のEDCB制限が残るため、統合HTTPS入口を使う。

標準一覧に表示するのは、Bridgeで作成した**PC録画予約**の待機中・録画中・無効状態。
完了済み・取消済み、XA401録画番組のPC書き出しジョブは予約として混ぜない。
XA401本体に登録された予約の読み出しではない。番組時刻はPCで指定した録画予定であり、
取得していない放送EPG・映像音声形式を捏造しない。チャンネル番号はKonomiTVの実情報を優先し、
取得できなければ観測したnetworkId／serviceIdと局名を使い、番号は未取得とする。

一覧・詳細・プリセット取得と、予約のキャンセルに対応する。キャンセルはPCジョブだけを停止し、
録画ファイルやXA401の元録画を削除しない。予約作成・設定変更は既存の
`/api/xa401/recordings`管理画面を使用する。未実装の変更要求は501と案内を返し、成功したふりをしない。
標準画面のEDCB専用の新規予約機能やキーワード予約を提供する変更ではない。

安定した48bit予約IDを使い、JavaScriptの整数精度を保つ。衝突は503にして誤った対象を取消さない。
既存のHost／Origin／LAN境界を維持し、チャンネル問い合わせは時間・サイズを制限する。
同時刻に使う異なる局数を数えて2枠との競合を表示する。同一局の共有は1枠扱い。
将来の視聴による枠消費までは予測できないため、録画完了の保証ではない。

人工予約の一覧・詳細・取消・完了済み除外・ID衝突・チャンネル取得失敗・枠競合をテスト。
KonomiTVの実schemas.Reservationsでも非空の合成レスポンスを検証した。Python全65検査が成功。
実サイトで一覧200／実予約0件・プリセット200を確認。元のPCジョブ1件は完了済みであり、
実予約を隠した空リストではない。異なるOriginは403。検証のための実予約作成・取消、
KonomiTVのDB書き込みは実行していない。
