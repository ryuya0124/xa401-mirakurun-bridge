# KonomiTVの録画管理への入口・Originalの起動待ち

オプションのKonomiTV連携パッチに、録画予約ホームと録画予約一覧の「PC録画を管理」ボタンを追加した。
リンクは同一originの/api/xa401/recordingsへ通常のページ遷移で開く。Vue Routerの未定義画面や
PWAの画面代替へ入らず、別タブも作らない。スマホ縦画面ではカードを縦配置する。
PC録画管理側にもKonomiTVの録画予約へ戻るリンクを置く。

パッチを既に入れている場合は以前のパッチを逆適用してから新版を適用し、クライアントを再ビルドする。
変更済みファイルを強制上書きしない。適用済みかはinstall_konomi_integration.pyが検査する。
サーバーコード・DBの変更やKonomiTV再起動は不要。PWAに更新通知が出たら更新して再読み込みする。
配備時は旧入口xa401-original.htmlもdeploy/xa401-original.htmlからdistへ戻す。

2026-11-16の1局で、Bridgeから最初のTSまで約2.21秒、メタデータ90ms・認証完了184ms。
認証の所要時間は約70msで、待ちの大半は認証後のTS到着だった。
KonomiTV経由の初回TSも約2.19秒。同一受信を共有できたHTTPS要求は約76msだった。
これは最初のTSまでの計測で、映像が表示されるまでの時間ではない。

クライアントには通常4秒の初期再生バッファ待ちがあったため、MPEG-2 Originalの最初の再生のみ
0.9秒（Safari 1.2秒）を上限にした。他の画質・通常の同期設定・保存済みのユーザー設定は変更しない。
画質、AKE、機器照合、SRMや鍵の取り扱いを変更しない。初期のバッファ余裕が小さくなるため、
通信の揺らぎが大きい環境では途切れやすさを別途観察する必要がある。
チャンネル切替で古い再生準備が残った場合も、新しい動画へ状態を反映しないようにした。

Bridgeのhealth/セッション状態にstartup_msを追加し、metadata／media_info／認証開始・完了／first_tsを
単調増加時計で記録する。ログには鍵、証明書、任意の認証例外の詳細を出さない。
初期バッファ短縮後の映像表示時間と長時間の安定性は未計測。チューナー起動自体が短くなったとは扱わない。

ESLint、型検査、本番ビルド、Python65検査が成功。連携パッチは未変更の対応HEADへ適用と逆適用を確認。
実サイトから新ボタンのJSと短縮済みプレイヤーJSを取得でき、予約ホーム・一覧・管理画面・旧入口が200。
ブラウザー操作／目視は利用者指定により行っていない。
