# 実機検証 2026-11-15

## 確認できたこと

- Windows上の独立venvから、実XA401のUDNとモデルを確認し、DMSからライブ133サービスを取得した。
- KonomiTVの互換API接続で地デジ35・BS26・CATV68の表示対象を取得した。これは視聴契約や全チャンネル再生の保証ではない。
- 放送チャンネル1つについてPCのAKEが完了し、暗号化PCPを復号した188バイトTSを配信できた。Androidを受信・復号・中継には使用していない。
- XA401の`original`リソースはMPEG-2 1440×1080、AAC。`mobile1`はH.264 1280×720である。
- KonomiTVのOriginal APIへ16 MiBを通してもMPEG-2 1440×1080とAACを維持した。サーバーログの処理は`Original MPEG-TS stream passthrough`。このモードでNVEncCによる映像再圧縮は実行しない。
- 元の橋渡しTSとKonomiTVのOriginal出力を同時に受信して比較した。映像の異なる64 KiBブロック3個と、主音声の異なる4 KiBブロック3個が、時間の重なる範囲でバイト単位に一致した。[元の比較結果](verification_2026-11-15.json)。コンテナー全体や番組全体の完全一致を主張する検査ではない。
- KonomiTV出力の映像・主音声をFFmpegで5秒デコードし、終了0を確認。ただし中途接続の先頭にMPEG-2ヘッダー未取得の`Invalid frame dimensions 0x0`ログがあった。ログが完全に空という結果ではない。
- 初回Original起動は1回の実測で約2.97秒でONAirへ移行した。恒常的な速度を保証する値ではない。
- 旧安定版の720p NVEncC変換も実動作したが、元画質を優先するため採用経路から外した。
- 自動テスト19件成功。仮想デバイスのテスト成功と、上記の実機結果は別々の証拠である。

## 端末・移行

Windowsの専用venvは実測約39 MiB、今回のKonomiTV配置は約1,205 MiB（Gitの管理領域を除く）。録画の保存量や今後のキャッシュは含む固定上限ではない。Debian候補はN100／16 GiB／空き約55 GiBだったが、利用者指定で今回の実行ホストはWindowsとした。Ubuntu・macOS上での実機受信は未検証。

## 未確認・制約

- Computer Useを使わずHTTP/APIと実デコードで検査した。実ブラウザーでの映像・音声表示は利用者の確認待ち。
- スマホ用HTTPSはLAN接続を準備。Windowsの実行権限ではファイアウォール規則を追加できず、管理者スクリプトを用意した。LAN到達・スマホ実再生は別途確認する。
- 同時に異なるチャンネルはアプリで1に制限。同じチャンネルは共有できる。3チャンネル同時受信・N100での3チャンネル処理は未検証。
- 今回の元画質・mobile1の取得区間にはEIT PID 0x12がなかった。時刻を創作せずEPG APIは空。DMSの現在番組名は独自の参照用APIで確認できる。
- KonomiTVのOriginalはTSフィルターを通すため、PMT・PID・副音声の補完などが入力と異なる場合がある。主映像・主音声の再圧縮をしないことと、全TSバイトが同じことを混同しない。
- Originalでもブラウザー内でMPEG-2を表示用に変換する。最終画面の画素が完全一致する、端末負荷がゼロ、どのスマホでも動くとは主張しない。
- 秘密の値・映像・PCAP・ベンダーのDLLはGitへ含めない。資格情報は外部へ送っていない。
